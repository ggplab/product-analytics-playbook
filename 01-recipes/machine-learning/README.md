# Machine Learning Fundamentals / 머신러닝 기초 개념

지도학습(분류·회귀)과 비지도학습(군집)의 핵심 개념을, 데이터 분석 실무에서 "언제 어떤 걸 고르나"를 기준으로 정리했습니다. `scikit-learn` 생태계를 기준으로 하며, 전처리 → 분류 → 회귀 → 군집 순서로 진행합니다.

---

## 1. Preprocessing / 전처리

### Train/Test Split / 학습·검증 분할

데이터를 학습용과 평가용으로 나눠, 모델이 처음 보는 데이터에서도 작동하는지 확인합니다. `train_test_split`.

> 실무에서 언제 쓰나: 모든 모델링의 첫 단계. 평가 데이터가 학습에 새면(leakage) 성능이 부풀려진다.

### Scaling / 스케일링

피처마다 값의 범위가 다르면 일부 모델이 큰 값에 끌려갑니다.

- **MinMaxScaler**: 0~1 범위로 압축.
- **StandardScaler**: 평균 0, 표준편차 1로 표준화.
- **Normalizer**: 행(샘플) 단위로 크기를 1로 맞춤(L2). 피처 척도가 크게 다를 때 군집 전처리에 유용.

거리·크기에 민감한 모델(선형모델·신경망·KNN·PCA)은 스케일링이 필요하고, 값의 대소 비교로 분기하는 트리 계열(결정트리·랜덤포레스트·부스팅)은 대체로 불필요합니다.

> 실무에서 언제 쓰나: 거리 기반·경사하강 기반 모델을 쓸 때는 거의 필수. 트리 계열만 쓸 거면 생략해도 된다.

### Encoding / 인코딩

범주형 변수를 숫자로 바꿉니다.

- **원-핫 인코딩(OneHotEncoder / `pd.get_dummies`)**: 명목형(순서 없음 — 혈액형)에 사용.
- 순서형(순서 있음 — 등급 A~D)은 순서를 보존하는 정수 매핑이 적절합니다.

> 실무에서 언제 쓰나: 범주형 피처를 모델에 넣기 직전. 순서형에 원-핫을 쓰면 순서 정보를 버리게 되니 구분해서 적용한다.

### Class Imbalance / 클래스 불균형

한쪽 클래스가 압도적으로 많으면 모델이 다수 클래스만 맞히고도 정확도가 높게 나옵니다. **SMOTE**(소수 클래스 오버샘플링)나 다수 클래스 언더샘플링으로 균형을 맞춥니다.

> 실무에서 언제 쓰나: 이탈·사기·불량처럼 관심 클래스가 희귀한 문제. 이때 정확도(accuracy)는 함정 지표이니 재현율·F1을 함께 본다.

## 2. Classification / 분류

### Loss vs Metric / 손실함수와 평가지표

- **손실함수(loss)**: 모델이 학습 중 최소화하는 대상(분류는 크로스 엔트로피).
- **평가지표(metric)**: 사람이 성능을 판단하는 잣대(정확도·F1). 회귀에서는 MSE·MAE가 둘 다로 쓰이지만, 분류에서는 학습용 손실과 평가용 지표가 갈린다.

> 실무에서 언제 쓰나: 모델이 낮추는 값(loss)과 이해관계자에게 보고하는 값(metric)을 구분해야 대화가 어긋나지 않는다.

### Precision, Recall, F1 / 정밀도·재현율

- **정밀도(precision)**: 양성이라 예측한 것 중 실제 양성 비율(모델 관점).
- **재현율(recall)**: 실제 양성 중 모델이 잡아낸 비율(데이터 관점).
- **F1**: 둘의 조화평균.

> 실무에서 언제 쓰나: 스팸 오탐이 비싸면 정밀도, 암·사기 누락이 치명적이면 재현율을 우선한다. 불균형 데이터의 표준 지표.

### AUC-ROC / ROC 곡선과 AUC

분류 임계값(기본 0.5)을 바꿔가며 참양성률과 거짓양성률의 트레이드오프를 그린 곡선이 ROC이고, 그 아래 면적이 AUC입니다. 좋은 분류기일수록 곡선이 좌상단으로 붙습니다.

> 실무에서 언제 쓰나: 임계값을 아직 정하지 않은 상태에서 모델의 전반적 분별력을 비교할 때. 의료 진단처럼 임계값 조정이 중요한 문제에 특히 유용.

### Tree-based Models / 트리 계열 모델

- **결정트리(Decision Tree)**: 값 비교로 데이터를 분기. 순수해질 때까지 키우면 과적합되므로 `max_depth`·`min_samples_split`로 가지치기.
- **랜덤포레스트(Random Forest)**: 여러 트리를 배깅(bootstrap + aggregating)으로 앙상블. 안정적.
- **부스팅(Boosting)**: 이전 모델의 오차를 다음 모델이 보완하며 순차 학습. 성능은 높지만 튜닝 민감.

> 실무에서 언제 쓰나: 정형 데이터(tabular)의 기본 선택지. 빠른 베이스라인은 랜덤포레스트, 성능을 짜낼 땐 부스팅.

### SVM & KNN / 서포트 벡터 머신과 최근접 이웃

- **SVM**: 클래스를 가르는 초평면(hyperplane)을 찾되, 경계에서 가장 가까운 점들까지의 여백(margin)을 최대화.
- **KNN**: 가까운 이웃의 다수결로 분류. 거리 기반이라 스케일링이 중요.

> 실무에서 언제 쓰나: SVM은 피처 대비 표본이 적은 고차원에서, KNN은 빠른 프로토타이핑이나 베이스라인으로.

### Parametric vs Non-parametric / 모수적·비모수적 방법

t검정·선형회귀·로지스틱회귀처럼 분포/형태를 가정하는 것이 모수적, KNN처럼 가정 없이 데이터에서 직접 배우는 것이 비모수적입니다.

> 실무에서 언제 쓰나: 데이터가 가정을 만족하지 못할 때 비모수 모델이 더 견고할 수 있다는 감을 잡는 데.

## 3. Regression / 회귀

### Linear Regression Assumptions / 선형회귀의 가정

선형회귀를 신뢰하려면 네 가지 가정을 점검합니다.

- **선형성(linearity)**: X와 Y의 관계가 선형.
- **독립성(independence)**: 독립변수 간 과도한 상관(다중공선성) 없음 — 상관 히트맵으로 확인.
- **잔차 정규성(normality)**: 잔차가 정규분포 — Q-Q plot, Shapiro-Wilk.
- **등분산성(homoscedasticity)**: 예측값 전반에서 잔차 분산이 일정 — 잔차 플롯으로 확인.

> 실무에서 언제 쓰나: 회귀계수를 "해석"하려는 순간 가정 점검이 필수. 가정이 깨지면 계수와 p-value를 믿기 어렵다.

### Regularization: Ridge & Lasso / 정규화

과적합과 다중공선성을 억제하려고 계수 크기에 페널티를 겁니다.

- **Lasso(L1)**: 계수 절댓값 합을 제약. 일부 계수를 0으로 만들어 **피처 선택** 효과.
- **Ridge(L2)**: 계수 제곱합을 제약. 모든 계수를 고르게 줄여 **다중공선성** 완화.

> 실무에서 언제 쓰나: 피처가 많고 서로 상관될 때. 불필요한 변수를 쳐내고 싶으면 Lasso, 전반적 안정화가 목적이면 Ridge.

### Polynomial Regression / 다항 회귀

`PolynomialFeatures`로 비선형 항을 만들고 `make_pipeline`으로 전처리→모델을 묶어 곡선 관계를 학습합니다.

> 실무에서 언제 쓰나: 관계가 뚜렷이 휘어 있을 때. 단, 차수를 높일수록 과적합 위험이 커진다.

### Regression Metrics / 회귀 평가지표

- **MSE / MAE**: 예측 오차의 크기. MSE는 단위에 의존하므로 절대적 품질이 아니라 모델 간 상대 비교용.
- **R²(결정계수)**: 평균 예측(기준선) 대비 설명력. 0이면 평균 수준, 1이면 완벽. `sklearn.metrics.r2_score`.

> 실무에서 언제 쓰나: 모델 비교엔 같은 데이터에서의 MSE, 이해관계자 소통엔 "분산의 몇 %를 설명"하는 R².

### Multicollinearity / 다중공선성

독립변수들끼리 강하게 상관된 상태. 계수 추정을 불안정하게 만듭니다. 스케일링으로는 해결되지 않고, 변수 제거·Ridge·PCA 등이 필요합니다.

> 실무에서 언제 쓰나: 회귀계수 부호가 직관과 반대로 튀거나 표준오차가 클 때 가장 먼저 의심할 것.

### Cross-validation / 교차검증

학습 데이터를 여러 폴드로 나눠 검증 폴드를 돌려가며 평가합니다(`cross_val_score`). 한 번의 분할이 주는 운을 줄입니다.

> 실무에서 언제 쓰나: 하이퍼파라미터를 고르거나 모델을 비교할 때. 단일 test 성능만 믿지 말고 교차검증으로 안정성을 확인한다.

## 4. Clustering / 군집

### K-Means & Choosing k / K-평균과 군집 수 선택

거리 기반으로 데이터를 k개 군집으로 묶습니다. 적절한 k는 두 방법으로 찾습니다.

- **엘보우 방법(elbow)**: 군집 내 응집도(SSE/WCSS)를 k에 대해 그려, 감소가 꺾이는 지점을 선택.
- **실루엣 점수(silhouette)**: 군집 내 응집(가까움)과 군집 간 분리(멀음)를 함께 반영. 높을수록 좋은 군집.

> 실무에서 언제 쓰나: 고객 세분화 등에서 "몇 개 그룹으로 나눌까"를 근거 있게 정할 때. 엘보우와 실루엣을 함께 본다.

### DBSCAN / 밀도 기반 군집

밀도가 높은 영역을 군집으로 묶고 희소한 점은 노이즈로 처리합니다. 군집 수를 미리 정하지 않아도 되고 임의 형태 군집에 강합니다.

> 실무에서 언제 쓰나: 군집 개수를 모르거나 구형이 아닌 군집·이상치가 섞인 데이터.

### PCA / 주성분 분석

타깃 없이(비지도) 피처의 분산을 최대한 보존하며 차원을 축소합니다. 다중공선성 완화와 시각화에도 쓰입니다.

> 실무에서 언제 쓰나: 피처가 너무 많아 시각화·모델링이 어렵거나, 상관 높은 변수들을 압축하고 싶을 때.
